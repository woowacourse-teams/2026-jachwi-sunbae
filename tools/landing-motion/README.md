# 랜딩과 사용 방법 영상

랜딩(`/landing`) 첫 화면의 소개 영상과 사용 방법(`/guide`)의 시나리오 영상을 만든다.

## 실행 준비

Node.js 20 이상이 필요하다. 이 폴더에서 실행한다.

```bash
npm install
npm run setup     # Playwright용 Chromium 설치, 처음 한 번만
```

## 랜딩 소개 영상

`intro.html` 한 장으로 그린 1920×1080, 29.7초 영상이다. 거리 메모 말풍선, 매물 사진 카드 마커, 조건 패널, 매물 상세 화면, 비교표, 계정 연결 화면을 지금 앱과 같은 모양, 색, 에셋(`assets/`)으로 옮겼고, 글꼴은 Pretendard다. 랜딩(`/landing`) 첫 화면이 이 영상을 `landing-intro.mp4`로 튼다.

```bash
node render.mjs --page intro.html --size 1920x1080 --shots 1.2,6.9,11,19.9,25   # 주요 시점 스틸을 out/에 저장
node render.mjs --page intro.html --size 1920x1080 --fps 30 --out out/jachwi-flow.mp4
```

- 스틸은 `out/intro-shot-<초>.png`로 저장한다.
- 폰트를 CDN에서 불러오므로 렌더링할 때 인터넷 연결이 필요하다.
- 브라우저에서 `intro.html#play`를 열면 실시간으로 재생하고, `intro.html#t=10.5`를 열면 그 시점에 멈춘 화면을 보여준다.
- 앱 녹화 클립(H.264 MP4)을 페이지에 넣으면 코덱이 있는 Chrome으로 렌더링해야 하므로 `--channel chrome`을 붙인다. 지금 `intro.html`은 클립을 쓰지 않는다.

렌더링한 MP4는 해상도를 그대로 두고 다시 압축해서 `frontend/src/pages/landing/assets/landing-intro.mp4`로 넣는다. 데스크톱 랜딩에서 영상 칸은 1440px 화면에서 710px, 1920px 화면에서 764px라 2배 밀도에서 1,420~1,528px가 필요하므로 1920px를 줄이지 않는다.

```bash
ffmpeg -i out/jachwi-flow.mp4 -c:v libx264 -preset slow -crf 28 -profile:v high -pix_fmt yuv420p -an \
  -movflags +faststart ../../frontend/src/pages/landing/assets/landing-intro.mp4
```

2026-11 기준 30fps 렌더링(crf 18, 8.1MB)을 crf별로 압축해 원본과의 SSIM(`ffmpeg -lavfi ssim`, 전체 프레임 평균 All)을 쟀다. crf 28을 쓴다.

| crf | 용량   | SSIM   | 가장 낮은 프레임 |
| --: | -----: | -----: | ---------------: |
|  26 | 3.62MB | 0.9954 |           0.9653 |
|  27 | 3.31MB | 0.9948 |           0.9617 |
|  28 | 3.01MB | 0.9942 |           0.9577 |
|  29 | 2.76MB | 0.9935 |           0.9534 |
|  30 | 2.53MB | 0.9928 |           0.9482 |
|  32 | 2.16MB | 0.9910 |           0.9373 |

- 비교표, 조건 패널, 매물 카드 글자는 crf 30까지 원본과 눈으로 구분되지 않았다.
- 차이는 첫 5초(동네 찾기)의 촘촘한 골목 지도에서 난다. 줌아웃하는 동안 가는 골목선이 crf가 올라갈수록 뭉개져, 이 구간 평균 SSIM이 crf 26에서 0.987, crf 28에서 0.983, crf 30에서 0.979다.
- crf 28이 3MB 목표에 맞고 옛 영상과 같은 SSIM(0.994)을 지킨다. 골목선이 더 선명해야 하면 crf 26(3.6MB)을 쓴다.

### 수정 방법

모든 움직임은 `intro.html`의 `window.__seek(t)` 하나가 시간 `t`(초)만 보고 계산한다. 타이머나 CSS 애니메이션을 쓰지 않으므로 시간 값만 바꾸면 타이밍이 바뀐다. `intro.html`은 옛 랜딩 영상(`flyover.html`)의 지도, 비행, 방, 비교표 장면을 그대로 두고, `SEGS`가 소개 영상의 각 구간을 옛 영상의 어느 시각에 대응시킬지 정한다.

| 바꿀 것                         | 위치                                       |
| ------------------------------- | ------------------------------------------ |
| 장면 순서와 길이                | `SEGS`                                     |
| 장면 제목과 설명                | `CH`                                       |
| 색, 폰트                        | 맨 위 `:root` 토큰                         |
| 행정동 경계                     | `assets/dongs-pangyo.js`(`dongs.py`로 만듦) |
| 통근 색                         | `COMMUTE`                                  |
| 비행 속도와 템포                | `BURSTS`, `CRUISE`                         |
| 지도 위 메모와 매물 마커        | `SPEC`                                     |
| 매물 정보와 체크리스트          | `FIELDS`, `CHECKS`                         |
| 체크리스트 항목 메모            | `NOTE`                                     |
| 비교표 값                       | `ROWS_T`                                   |
| 한 끼와 날씨 카드               | `MCARDS`                                   |

행정동 경계는 `frontend/data/admin-dongs.geojson`에서 판교역 주변을 영상 좌표로 옮겨 단순화한 것이다. 바꾸려면 저장소 루트에서 `python3 tools/landing-motion/dongs.py`를 실행한다.

### 옛 랜딩 영상

`flyover.html`은 #663 전까지 랜딩이 틀던 1440×1152, 17초 영상(`landing-flyover.mp4`)이다. `intro.html`이 이 파일의 장면을 바탕으로 만들어졌으므로 남겨 두고, 아래 명령도 그대로 쓸 수 있다.

```bash
npm run shots           # 주요 시점 스틸을 out/flyover-shot-<초>.png로 저장
npm run render          # 1440×1152, 60fps MP4를 out/flyover.mp4로 저장
npm run render:preview  # 30fps로 빠르게 확인
```

## 사용 방법 영상

`record-guide.mjs`가 개발 서버(`dev.jachwi-sunbae.kr`)에서 휴대폰 화면(390×844)을 실제로 조작하며 네 편을 녹화한다. 누르는 자리에는 파란 원을 잠깐 띄운다.

```bash
node record-guide.mjs                           # 네 편 모두
node record-guide.mjs memo,property,checklist   # 일부만
```

| 영상        | 내용                                                       |
| ----------- | ---------------------------------------------------------- |
| `explore`   | 판교역을 검색하고 통근 30분 이내로 고른 뒤 1위 동네 열기   |
| `memo`      | 정자동 지도에서 자리를 골라 좋아요와 거리 메모 남기기      |
| `property`  | 매물을 추가하고 이름, 보증금, 월세 채우기                  |
| `checklist` | 그 매물의 체크리스트에서 괜찮음, 주의를 고르고 메모 남기기 |

결과는 `out/guide/guide-*.mp4`에 저장한다. 프런트에 넣을 때는 `frontend/src/pages/usage-guide/assets/`로 복사하고, 마지막 장면을 포스터(`guide-*-poster.jpg`)로 함께 뽑는다.

녹화는 `out/guide/state.json`의 익명 회원 하나로 이어서 한다. 다시 녹화할 때는 먼저 그 회원의 매물과 영상용 거리 메모를 지운다. 마지막 녹화의 매물과 메모는 체크리스트 영상에 쓰므로 개발 서버에 남는다. 거리 메모는 다른 사람에게도 보이므로, 필요 없으면 지운다.
