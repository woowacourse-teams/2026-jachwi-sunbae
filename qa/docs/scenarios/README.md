# Scenario

- 상태: v0.1 / 작성일: 2026-10-06

Scenario는 [사용자 흐름](../user-flows/README.md) 안의 **한 가지 상황을 어떻게 시험하고, 무엇을 증거로 남길지** 정한다.   
기대 동작은 명세의 인수 기준(`AC`)에서 가져오고, Scenario는 구체적인 데이터,단계, Evidence를 더한다.

## 작성 규칙

- ID는 `F<Flow 번호>-S<두 자리 번호>`, 파일 이름은 `<ID>-<영문 요약>.md`다. 예: `F02-S01-property-create.md`
- Scenario 하나는 상황 하나를 다룬다. Expected는 3~6개를 권장한다.
- 단계는 사용자 행동 단위로 쓴다. 화면 요소 선택자나 구현 세부는 쓰지 않는다.
- 모든 Expected에 근거 ID를 적는다. 근거가 없는 기대 동작은 Expected로 만들지 않는다.
- 각 Expected의 판정 방식을 정한다.
  - `코드`: 상태 코드, 값 일치, 요소 존재처럼 결정적으로 비교할 수 있다.
  - `AI`: 문구·화면 해석처럼 판단이 필요하다. AI 판정은 사람 확인 전까지 초안이다.
  - `사람`: 자동으로 판정하기 어렵다.
- 사전 조건을 갖추지 못하면 `BLOCKED`다. 원인이 제품 결함으로 보이면 Run Report의 기타 관찰에 남긴다.
- 새 Scenario를 만들면 해당 Flow 문서의 Scenario 표에도 추가한다.

## 상태

| 상태 | 의미 |
| --- | --- |
| 초안 | 작성했지만 사람이 아직 검토하지 않았다. |
| 승인 | 사람이 검토해 실행 기준으로 확정했다. 자동화는 승인된 Scenario만 한다. |
| 자동화 | 자동 실행 코드가 있다. 실행 방식에 코드 위치를 적는다. |

## 공통 실행 조건

- 대상 환경과 테스트 데이터 원칙은 [QA 안내](../../README.md)를 따른다.
- `{runId}`는 실행마다 새로 만드는 `YYMMDD-HHmmss` 형식의 값이다. 예: `261006-143015`

## 작성 형식

```markdown
# F00-S00 Scenario 이름

| 항목 | 내용 |
| --- | --- |
| Flow | [F00 Flow 이름](../user-flows/F00-xxx.md) |
| 근거 | `AC-XXX-000`, `REQ-XXX-000` |
| 상태 | 초안 |
| 실행 방식 | 수동 |

## 목적

이 Scenario가 확인하려는 것을 한두 문장으로 쓴다.

## 사전 조건

- 실행 전에 갖춰야 할 상태

## 테스트 데이터

| --- | --- |

## 단계

## Expected

| --- | --- | --- | --- |
| E1 | | | 코드 · AI · 사람 |

## Required Evidence

## 판정 메모

- 이 Scenario에서 판정하지 않는 것

## 실행 기록
```
