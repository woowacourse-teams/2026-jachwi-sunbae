# F02-S02 보증금·월세 누락 등록

| 항목 | 내용 |
| --- | --- |
| Flow | [F02 후보 매물 등록](../user-flows/F02-property-create.md) |
| 근거 | `AC-PROP-002`, `POL-PROP-002` |
| 상태 | 초안 |
| 실행 방식 | 수동 |

## 목적

보증금 또는 월세를 비우고 등록하면 저장되지 않고, 사용자가 어떤 값이 빠졌는지 알 수 있는지 확인한다. 비운 값이 0으로 바뀌어 저장되지 않는지도 함께 본다.

## 사전 조건

- DEV 프론트엔드와 API에 접속할 수 있다.
- 새 닉네임 `qa-{runId}`로 비밀번호 없이 시작해 빈 매물 목록에 있다.

## 테스트 데이터

| 경우 | 이름 | 보증금 | 월세 |
| --- | --- | --- | --- |
| A | `F02-S02 A {runId}` | 비움 | `50` |
| B | `F02-S02 B {runId}` | `500` | 비움 |

## 단계

1. 매물 등록 화면으로 이동해 경우 A의 값을 입력하고 등록을 시도한다.
2. 화면을 확인한다.
3. 매물 등록 화면에서 경우 B의 값을 입력하고 등록을 시도한다.
4. 화면을 확인한다.
5. 매물 목록으로 이동한다.

## Expected

| ID | 기대 결과 | 근거 | 판정 방식 |
| --- | --- | --- | --- |
| E1 | 두 경우 모두 등록되지 않는다. 생성 성공 응답이 없고 상세 화면으로 이동하지 않는다. | `AC-PROP-002` | 코드 |
| E2 | 두 경우 모두 사용자가 화면에서 어떤 값이 빠졌는지 알 수 있다. | `AC-PROP-002` | AI |
| E3 | 비운 값이 0으로 바뀌어 저장되지 않는다. 시도 후 매물 목록이 비어 있다. | `AC-PROP-002`, `POL-PROP-002` | 코드 |

## Required Evidence

| ID | Evidence | 확인 대상 |
| --- | --- | --- |
| EV1 | 경우 A·B의 등록 시도 직후 화면 스크린샷 | E1, E2 |
| EV2 | 등록 시도 중 매물 생성 요청과 응답. 요청이 없었다면 없었다는 기록 | E1 |
| EV3 | 매물 목록 화면 스크린샷과 목록 조회 응답(`GET /api/properties`) | E3 |

## 판정 메모

- 화면에서 막든 서버가 거부하든 저장되지 않으면 E1은 `PASS`다. API를 직접 호출하는 검증은 이 Scenario의 범위가 아니다.
- 안내 문구와 위치는 명세가 정하지 않았다. E2는 빠진 필드를 특정할 수 있으면 `PASS`, 전혀 알 수 없으면 `FAIL`, 판단이 갈리면 `NEEDS_REVIEW`다.
- 입력란이 처음부터 0으로 채워져 있어 비울 수 없다면, 미입력과 0을 구분하는지(`POL-PROP-002`) 판단이 필요하므로 `NEEDS_REVIEW`로 남긴다.
