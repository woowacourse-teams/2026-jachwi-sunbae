# F06-S01 체크 상태 저장과 진행 현황 집계

| 항목      | 내용                                                                                            |
| --------- | ----------------------------------------------------------------------------------------------- |
| Flow      | [F06 매물 체크 기록](../user-flows/F06-property-check.md)                                       |
| 근거      | `AC-CHECK-007`, `REQ-PROGRESS-003` ~ `REQ-PROGRESS-006`, `POL-PROGRESS-001`, `POL-PROGRESS-002` |
| 상태      | 초안                                                                                            |
| 실행 방식 | 수동                                                                                            |

## 목적

현장 체크리스트 항목의 상태를 고르면 즉시 저장되고, 진행 현황이 명세의 집계 규칙대로 계산되어 체크리스트·매물 상세·매물 목록에 일관되게 보이는지 확인한다.

## 사전 조건

- DEV 프론트엔드와 API에 접속할 수 있다.
- 새 닉네임 `qa-{runId}`로 비밀번호 없이 시작했다.
- [F02-S01](F02-S01-property-create.md)의 1~4단계와 같은 방식으로 매물 `F06-S01 {runId}`(보증금 500, 월세 50)를 등록했다.
- 등록한 매물에 현장 체크리스트가 적용되어 있고 항목이 4개 이상이다. 적용된 항목 수를 N이라 한다.

## 테스트 데이터

| 항목 순서 | 조작                             | 최종 상태 |
| --------- | -------------------------------- | --------- |
| 1번째     | 괜찮음 선택                      | 괜찮음    |
| 2번째     | 주의 선택                        | 주의      |
| 3번째     | 주의 선택                        | 주의      |
| 4번째     | 괜찮음 선택 후 미확인으로 되돌림 | 미확인    |
| 나머지    | 조작하지 않음                    | 미확인    |

## 단계

1. 등록한 매물의 상세에서 현장 체크리스트를 열고 적용된 항목 수 N을 기록한다.
2. 테스트 데이터대로 1~4번째 항목의 상태를 고른다. 별도 저장 버튼은 누르지 않는다.
3. 체크리스트의 진행 현황을 확인한다.
4. 브라우저를 새로고침하고 각 항목 상태와 진행 현황을 다시 확인한다.
5. 매물 상세의 현장 체크 집계를 확인한다.
6. 매물 목록의 현장 체크 집계를 확인한다.

## Expected

| ID  | 기대 결과                                                                                            | 근거                                                                       | 판정 방식                     |
| --- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------- |
| E1  | 상태를 고를 때마다 저장 요청이 성공한다. 새로고침 후 항목 상태가 괜찮음·주의·주의·미확인이다.        | `REQ-PROGRESS-003`                                                         | 코드                          |
| E2  | 진행 현황이 전체 N, 완료 3, 괜찮음 1, 주의 2, 미확인 N−3, 진행률 floor(300 ÷ N)%다. N이 8이면 37%다. | `AC-CHECK-007`, `REQ-PROGRESS-004`, `POL-PROGRESS-001`, `POL-PROGRESS-002` | 코드                          |
| E3  | 새로고침 후에도 진행 현황이 E2와 같다.                                                               | `REQ-PROGRESS-003`                                                         | 코드                          |
| E4  | 매물 상세의 현장 집계가 E2와 일치한다.                                                               | `REQ-PROGRESS-005`                                                         | 코드. 표기 해석이 필요하면 AI |
| E5  | 매물 목록의 현장 집계가 E2와 일치한다.                                                               | `REQ-PROGRESS-006`                                                         | 코드. 표기 해석이 필요하면 AI |

## 판정 메모

- `AC-CHECK-007`은 3항목 양식 예시다. 사용자 양식을 준비(F05)하지 않고 실행하려고 시스템 기본 현장 양식으로 같은 규칙(`POL-PROGRESS-001`, `POL-PROGRESS-002`)을 검증한다. 3항목 예시 그대로의 검증은 F05 Scenario를 만든 뒤 추가한다.
- 진행률을 내림이 아니라 반올림하면(N이 8일 때 38%) `POL-PROGRESS-002` 위반으로 `FAIL`이다.
- 상세·목록에 어떤 집계 값을 보여줄지(진행률만, 완료/전체 등)는 명세가 정하지 않았다. 보이는 값이 E2와 모순되지 않으면 `PASS`다.
- 이 Scenario에서 판정하지 않는 것: 항목 메모 저장, 계약 전 단계, 양식 교체.
