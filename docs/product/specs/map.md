# 지도·주소·주변 분석 기능 명세

- 상태: 검토용 초안 v0.1 / 작성일: 2026-09-13 / 대상: MVP1-2

## 1. 목적과 범위

사용자는 매물 위치를 선택하고 주변 시설을 확인한다.

지도 표시, 주소 검색 결과 선택, 좌표의 주소 변환, 대체 위치, 시설 필터와 조회 실패를 다룬다.

## 2. 요구사항

- `REQ-MAP-001`: 일반 지도에서 사용자가 현재 위치 조작을 실행하면 위치를 요청하고 성공 시 그 위치를 표시한다.
- `REQ-MAP-002`: 위치 조회 실패 시 모든 관련 화면의 대체 위치로 우테코 판교 사옥을 사용한다.
- `REQ-MAP-003`: 자신의 매물을 지도 핀으로 확인하고 선택한 매물의 주변 분석으로 이동한다.
- `REQ-MAP-004`: 지도에서 고른 좌표의 주소를 확인한다. 현재 위치 조회·좌표의 주소 변환 실패 시 대체 주소·위치를 사용한다.
- `REQ-MAP-005`: 지도 선택 또는 주소 검색 결과 선택으로 주소·좌표를 매물 등록·수정에 전달한다.
- `REQ-MAP-006`: 주변 조회 반경을 선택한다.
- `REQ-MAP-007`: 병원·교통·학교·편의점·중개사무소의 조회 결과와 개수를 확인한다.
- `REQ-MAP-008`: 신규 선택·수정·주변 분석의 시작 위치를 화면 목적에 맞게 정한다.
- `REQ-MAP-009`: 모든 시설 필터는 한 번에 한 카테고리만 선택한다.
- `REQ-MAP-010`: 최초 진입 시 시설 카테고리는 미선택이다.
- `REQ-MAP-011`: 위치 선택 중에도 현재 위치로 이동하는 조작을 제공한다.

## 3. 정책

### 3.1. 위치와 주소의 공통 기준

| 화면                | 시작 위치와 실패 처리                                                                                                    |
|---------------------|--------------------------------------------------------------------------------------------------------------------------|
| 일반 지도           | 마지막으로 본 위치를 사용하고 없으면 판교 사옥을 표시한다. 현재 위치는 사용자가 요청할 때 조회한다.                     |
| 신규 매물 위치 선택 | 이미 선택한 위치를 유지한다. 선택한 위치가 없으면 마지막으로 본 위치 또는 판교 사옥을 사용한다.                          |
| 매물 위치 수정      | 수정 중 선택한 위치, 저장된 매물 위치 순으로 우선한다. 둘 다 없으면 마지막으로 본 위치 또는 판교 사옥을 사용한다.         |
| 매물 주변 분석      | 해당 매물의 저장 위치를 사용한다. 매물은 존재하지만 위치를 확인할 수 없으면 판교 사옥을 대체 위치로 사용한다.            |

- `POL-MAP-001`: 주소와 좌표가 같은 선택 결과를 가리키도록 전달한다. 위도·경도는 함께 사용한다.
- `POL-MAP-002`: 주소 미입력 시 마지막으로 본 지도 위치를 사용하고, 없으면 우테코 판교 사옥 (금토로80번길 40)의 주소·위치를 사용한다. 현재 위치는 사용자가 위치 조작을 실행할 때만 요청한다.
- `POL-MAP-003`: 주소를 직접 타이핑하면 검색 결과를 선택해 확정한다.

### 3.2. 시설 카테고리·반경·개수

- `POL-MAP-004`: 반경은 500m·1km·2km를 지원하는 안을 둔다.
- `POL-MAP-005`: 시설 카테고리의 복수선택은 제공하지 않는다.
- `POL-MAP-006`: 처음에는 시설 카테고리를 선택하지 않는다. 다른 카테고리를 누르면 교체하고 같은 카테고리를 다시 누르면 해제한다. 매물 핀은 필터와 무관하게 유지한다.

| AC-MAP-007 | 주변 분석을 열고, 별도로 위치를 확인할 수 없는 더미 매물을 준비한다.       | 정상은 해당 매물 위치, 위치 확인 불가는 판교 사옥을 사용한다.         |

## 5. 미정 사항

### 지도 탭의 주변 시설 기준과 로컬 확인

- 매물 추가 모드에서도 500m·1km·2km와 시설 필터를 유지한다. GPS 권한 없이 중앙 선택 핀을 기준으로 조회하며, 반경 미선택이면 500m로 시작한다.
- 일반 탐색 반경은 마지막 선택 좌표에 고정하며 화면 이동을 따라가지 않는다. 매물 선택은 저장 좌표, 주소 검색은 검색 좌표, 현재 위치 버튼 성공 시에는 GPS 좌표를 기준으로 바꾼다. 반경 선택 시 500m는 지도 레벨 5, 1km는 6, 2km는 7로 변경하며 조회 기준 좌표는 유지한다. 같은 반경을 다시 눌러 해제할 때는 확대 수준을 유지한다. 추가 모드에서만 중앙 선택 핀의 이동을 따라간다.
- 매물 목록의 다음 페이지도 조회하고, 지도 SDK의 실제 표시 경계로 화면 안 매물을 판단한다. 선택한 매물은 묶음 대신 개별 핀으로 표시한다.
- 로고 마커를 SDK 요소로 변환할 때 React의 이미지 preload 링크가 아닌 실제 마커 루트를 사용한다.
- 매물 마커는 지도 확대 시 커지고 축소 시 작아지며 기본 크기의 0.7~1.36배로 제한한다. 확대 단계 변경만으로 SDK 마커를 재생성하지 않고 기존 요소의 크기 변수를 갱신한다. 현재 위치·시설 마커는 크기를 유지한다.
- 첫 진입에는 반경 버튼을 비활성화한다. 매물·주소 선택, 현재 위치 버튼의 GPS 조회 성공 또는 매물 추가 진입 후 활성화한다. 개별 매물 선택은 현재 확대 수준을 유지하며, 핀 끝을 실제 매물 좌표와 반경 중심에 맞춘다. 마커 크기가 바뀌어도 같은 끝점을 유지한다.
- 반경 버튼은 검색창 바로 아래 왼쪽에 표시하고 별도 상단 '위치 확인' 버튼은 사용하지 않는다. 실제 현재 위치 이동 아이콘은 시설 목록 아래에 계속 표시하며 재조회할 수 있다. 위치 확인 중·권한 허용·오류 안내는 이 아이콘 왼쪽의 토스트로 표시해 반경 버튼을 가리지 않는다.
- 매물 추가 모드의 중앙 핀 주변 시설 조회 안내 토스트는 표시하지 않는다.
- 웹과 `tab-bar-overlay` 지원 앱에서는 지도와 바텀시트 배경을 하단 탭 뒤까지 이어 표시한다. 시트의 카드·버튼은 탭 높이만큼 여백을 두어 가리지 않는다. 구버전 앱은 기존 WebView 아래 네이티브 탭 배치를 유지한다.
- 닫힌 시트를 끌어올리는 도중에도 목록·로딩·빈 상태를 표시한다. 닫힌 내용은 렌더링을 유지하되 접근성 트리와 키보드 탐색에서 제외해 드래그 중 흰 배경만 노출되지 않게 한다.
- 목록의 스크롤 높이는 드래그 중에도 실제 시트 노출 높이에서 손잡이와 탭 여백을 뺀 영역에 맞춘다. 탭 뒤에는 흰 시트 배경만 이어지며 매물 카드가 비치지 않는다.
- 매물을 선택한 상태에서 반경을 변경하면 새 확대 수준에 맞춰 해당 매물이 화면 왼쪽 위 기준 위치에 오도록 지도 중심을 다시 맞춘다. 시설 조회 좌표는 매물 좌표에 고정한다.
- 매물 선택 시 확대 수준은 유지하고 시설 조회 좌표를 해당 매물로 바꾸며, 지도 중심을 조정해 핀 끝이 화면의 왼쪽 위(가로 42%, 세로 40%)에 보이도록 한다. 선택 매물 시트는 카드 높이에 맞춰 불필요한 빈 공간을 줄인다. 구버전 네이티브 탭 앱은 별도 웹 탭 여백을 두지 않으며, `tab-bar-overlay` 지원 앱은 네이티브 탭 높이와 안전 영역만큼 콘텐츠를 보호한다.
- 로컬 `/map` 확인: GPS 권한 없이 추가 → 시설 선택 → 중앙 핀 이동 → 추가 취소 → 등록 매물 마커 선택 → 화면 이동·2km 변경 → 지도 빈 곳 클릭 → 지도 축소·창 크기 변경 순서로 확인한다.
- 매물 등록 폼의 별도 주소 선택 화면은 이번 수정 범위에 포함하지 않는다.
- 매물 마커 선택 시 선택 매물 카드 하나를 하단에 표시한다. 카드에서 상세로 이동할 수 있으며 지도 빈 곳 클릭 시 선택을 해제하고 시트를 접는다. 별도 X 버튼·상단 주변 시설 기준 선택창·매물 개수 헤더는 표시하지 않는다. 선택 해제 후에도 조회 기준 좌표는 유지한다.
- 개별 매물 마커는 검정 물방울 핀 안에 대표 사진이 있으면 사진, 없으면 오리 로고를 표시한다. 가격 문구는 표시하지 않는다. 지도 배경과 구분하도록 사진 테두리 2px를 사용하고 선택 시 같은 테두리를 3px로 강조한다. 별도 외곽선은 겹치지 않으며 묶음은 핀 대신 숫자 배지로 구분한다. 현재 화면 안의 매물 사진만 조회한다. SDK 좌표 이동용 래퍼와 마커 중심 정렬을 분리한다.
- 바텀시트는 매물 조회 전에도 접힌 손잡이(2.25rem)를 표시하며 내부 콘텐츠는 펼쳤을 때 로딩·오류·빈 목록 상태를 표시한다. 손잡이 클릭/드래그로 펼친다. 네이티브 탭이 웹뷰 아래 형제 뷰인 앱에서는 지도 내부의 중복 탭 여백을 제거한다. 웹은 웹 하단 탭 위에서 손잡이를 표시한다.
- MSW 지도 응답은 조회 좌표·반경·카테고리 조건을 반영한다. 역지오코딩은 가까운 샘플 매물의 주소를 사용하고, 그 외는 실제 주소로 오인하지 않도록 테스트 위치로 표시한다. 실제 운영 장소 데이터가 아닌 샘플이다.

- 시설 개수와 카테고리 범위 (#243)
    - 현재는 외부 API 호출량을 제한하기 위한 **임시 기준**으로 동작한다. 제품 정책은 이후 결정한다.
    - 임시 기준: 시설은 기준 위치에서 가까운 순으로 카테고리별 최대 45개까지 보여준다.
    - 결정할 것: 상한 값, 상한에 도달했을 때의 안내 ("45개 이상" 등), 카테고리별 포함 범위, 캐싱 처리 등등
- 주소 정보 출처 표시 (#251)
    - 주소 검색과 좌표의 주소 변환은 공공데이터 (행정안전부 도로명주소, 국가데이터처 SGIS)를 사용한다.
    - SGIS는 공공누리 제1유형 (출처표시)이므로 서비스 화면에 출처를 표시해야 한다. 운영 배포 전에 반영한다.
    - 결정할 것: 표시 위치 (위치 선택 화면, 서비스 정보 페이지 등)와 문구
- 버스정류장 데이터 조회 방식과 반경 확장
    - TAGO의 버스정류장은 기준 좌표 반경 500m까지만 제공한다.따라서 사용자가 1km·2km 반경을 선택해도 지하철역은 선택 반경까지 조회되지만 버스정류장은 최대 500m까지만 조회되는 한계가 있다.
    - 해결방법
        - 방법 1. 공공데이터의 좌표를 DB에 저장
        - 방법 2. TAGO를 쓰되, 주변 여러 좌표로 여러 번 쏴서 결과를 합침
        - 방법 3. 버스정류장만 500m 제공()
    - 방법 1로 해결할 예정.
